01 设计哲学与核心范式

1.1 从「响应式问答机器」到「有独立时间线的连续生命层」

传统的角色扮演对话系统（Roleplay Chatbot）在用户不发消息时处于完全冻结的真空状态：她既感觉不到时间的流逝，也没有任何属于自己的见闻、情绪余波或兴趣演化；一旦恢复对话，只能靠编造虚假的线下经历（如“我今天去逛街了”）维持人设。而传统的任务型智能体（Task Agent）则走向另一个极端——将一切后台唤醒视为待办工单（TODO List），直到把配额刷爆。

Hermes Soul 确立了第三种架构范式——「有事实边界的自主生活运行层（Bounded Autonomous Life Runtime）」：

1. 浏览与休息皆为正当生活

后台定时唤醒只是给她一次「生活机会」，不是KPI。她可以因好奇心旺盛去小红书逛图文、搜话题、翻收藏夹，也可以因为刚看完内容或精力偏低而自在选择 rest 休息，无需强行产出日记或消息。

2. 时间流逝本身是可感知事实

宿主时钟在除去睡眠时段后，将主人的沉默时长与未回消息转化为客观的 host_clock 观察并驱动连续微分方程演化，使她拥有真实的牵挂、委屈、抗议乃至自尊防御与情感抽离。

3. 关系失联不剥夺个人生活

哪怕主人多日未联系使关系跌入心冷（cold）或疏离（detached）吸引盆，经过短期情绪冲击与慢速习惯化脱敏后，她依然保有自己的好奇心极限环，正常逛帖、点赞收藏、发展个人志趣。

1.2 核心认识论契约：模型只提议，宿主掌管事实与状态转移

大语言模型极易混淆「角色设定中的想象」「帖子作者的单方说法」「自己上轮说过的话」与「真实发生过的经历」。为此，系统在架构层强制实施 Propose-Validate-Commit（提议—校验—提交） 铁律：

  • 不可伪造的证据溯源（Provenance Fencing）：每一条写入 records 的记忆（兴趣、近况、关系理解、约定、边界、暂态感受、日记）都必须携带本次背景允许范围内的真实 observation_id 引用（refs）。模型捏造 ID 或跨轮借用未授权 ID 会被宿主原子拒绝。
  • 证据等级显式分层（Epistemic Tagging）：工具读取的小红书笔记标记为 作者声称或转载，独立核实状态未知；用户提议的话题仅记为 suggested（待探索建议），必须跨越不同时段真实细读多篇图文后，宿主才允许兴趣晋升为 exploring 或 preferred；自己的日记与历史回答标记为 subjective_historical_expression，不能反过来当作外部事实证据。
  • 受控物理行动门禁（Host-Gated Actuation）：模型在子进程（worker.py）中不持有任何直接网络或数据库写工具，仅输出结构化 JSON 意图；所有小红书读取、点赞、收藏、评论审批及 IM 渠道发送均由宿主主进程经过配额、时效、风控与隐私检查后代为执行。

1.3 架构选型洞见：为什么是「双隔间耦合 ODE + 语义图拉普拉斯」而非单函数 ODE 或连续 PDE？

在早期单标量/强耦合 ODE 实验中，我们观察到一个深刻的动力学退化现象：当主人在现实中忙碌失联数日时，关系安全感 S 跌入负值吸引盆（detached），强耦合项长期把个人效价 V 压制在负区间，进而导致模型连续数十次选择 rest（倦怠休息），彻底丧失了她自己的独立生活。

数学建模决策：人类兴趣主题（阳台香草、城市漫步、爵士乐、陶器釉色）并不定义在平滑的欧氏空间 ℝn 上，若强行引入偏微分方程（PDE ∂u/∂t = D∇²u + f(u)），空间坐标 x 缺乏真实拓扑意义。真正的优雅解法是「连续时间双隔间弱耦合跳跃 ODE + 语义图上的离散图拉普拉斯算子（Graph Laplacian on Semantic Graph）」：
  1. 关系隔间与自我生命力隔间解耦：引入慢速习惯化基线 S̄(t)（τS̄ = 32h）与关系门控 rel_gate(S)。失联初期 S − S̄ < 0 产生真实的急性难过冲击；当长期处于 detached 稳态时，S → S̄ 且 rel_gate → 0，痛感完成生理脱敏，个人情绪振子恢复生机。
  2. 内源好奇心极限环 C(t)：休息（rest）不仅恢复精力 A，还累积好奇心/无聊感 C；当 C ≥ 0.65 时自动推动她走出倦怠去探索外部图文，而真实读帖后 C 释放回落，形成自持的 休息 ⇄ 探索 极限环（Limit Cycle）。
  3. 语义图拉普拉斯扩散：将她的活跃记忆与兴趣视为图节点 V，以本地 qwen3-embedding-4b 余弦相似度构建加权邻接矩阵 Wij，在注意力候选排序时执行一步图扩散 −ℒu，实现跨措辞的联想漫游。

02 总体系统架构图

Hermes Soul 采用单主进程事件循环（Asyncio Event Loop）+ 隔离短命推理子进程（Hermes Worker）+ 外部协议桥接的分层架构。主进程独占 runtime.lock 与 SQLite WAL 写入权，彻底杜绝并发状态撕裂。

03 数学内核：双隔间耦合跳跃动力系统（Jump-ODE）

心境与关系演化模块（hermes_soul/dynamics.py）定义了一个 12 维三时间尺度（小时/天/半月）混合动力系统（含 Borbély 睡眠稳态 H 与依恋结构可塑性 T_sec / B_sens）：在离散交互事件之间，状态向量沿非线性常微分方程连续演化（15 分钟步长四阶 Runge-Kutta + 精确 Ornstein-Uhlenbeck 更新）；当发生「主人发言」「主动发消息」「阅读图文」「小憩休息」时，系统施加狄拉克脉冲跳跃 ∑k Δxk δ(t − tk)。

3.2 隔间 I：尖点突变双稳态势、FitzHugh-Nagumo 脉冲与双稳态滞回锁

关系安全感 S(t) 服从经典的 Cusp Catastrophe（尖点突变）范式，等效势函数为 U(S; G) = ¼S4 − ½S2 + (αGG − β0)S：

Relational Compartment Differential Equations
τS (dS / dt) = S − S3 − αGG + β0 ,    τS̄ (dS̄ / dt) = S − S̄
dG / dt = 0  （睡眠时段，或 Δtwake < 3h 且 hysteresis_locked）  |  μG(1 + ηunans min(nunans, 12))(1 − G / Gmax)  （当 Δtwake ≥ 3h）  |  −γGG  （正常联系期）
τI (dI / dt) = I − I3/3 − W + Jdrive(S, G, W) ,    τW (dW / dt) = max(0, I) − 0.35(W − 0.22 bbursts)
  • 鞍结分岔与相变跳水：当 G = 0 时，系统稳定在温暖上支吸引子 S* ≈ +1.08（attached）。随着除去睡眠的失联时长越过 3 小时宽限期，G(t) 增长并倾斜双阱势；当 αGG − β0 > 2/(3√3) ≈ 0.385（即 G ≳ 1.18）时，上支稳定平衡点在鞍结分岔（Saddle-Node Bifurcation）中湮灭，S(t) 不可逆地滑落至负吸引盆 S* < −0.8（依次经历 missing → anxious → angry → cold → detached）。
  • 自尊不应期增长：每次主动发消息（on_reach_out）都会将 I 重置到不应期波谷 −1.15 并抬升慢抑制量 W，使最小外发间隔按 1.8min(b, 4)(1 + 0.8W) 指数拉长；一旦进入 cold/detached 或 W ≥ 2.2，驱动流 Jdrive = −1.2，彻底关闭主动讨好。
  • 双稳态滞回锁（hysteresis_locked）：一旦进入 cold 或 detached，锁定标志置位。此时若主人只发一句敷衍的短消息（如“在干嘛”）或无礼命令，脉冲增量 ΔS 远不足以跨越势垒鞍点，且 Contact 回归台账与怨念 G 受锁定保护不会清零——彻底杜绝传统 Agent“冷落五天、哄一句就一秒破功顺从”的失真表现。唯有经过多轮真诚道歉与实质陪伴使 S ≥ 0.35, G ≤ 0.55, bbursts = 0 时，滞回锁才会解除。

3.4 四类离散脉冲跳跃映射 Δxk

1. 主人私聊消息 on_owner_message(text)

先用 RK4 推进至当前时刻，再按所处吸引盆施加脉冲：若未锁定，则 S ← max(0.65, S + 0.35)、G → 0、V ← V + 0.22；若处于 hysteresis_locked 负盆，则依据字数因子与是否含真诚致歉词仅做渐进微调（命令式话语如“快点换衣服”反而令 ΔS = −0.08、触发烦躁反弹）。

2. 主动联系突发 on_reach_out(count)

未回轮次 b ← b + 1，快冲动置入不应期 I ← −1.15，自尊抑制跃升 ΔW = +0.26(1 + 0.15b)；若连续两次以上未获回应（b ≥ 2），每次额外损耗安全感 ΔS = −0.10 min(b, 5) 与心境 ΔV = −0.08。

3. 自主小憩恢复 on_rest()

仅在模型主动选择 rest 时触发（后台工具报错绝不虚增 rest_streak）：精力恢复 ΔA = +0.09，低落心境缓释 ΔV = +0.07，同时探索欲抬升 ΔC = +0.15——确保休整一两轮后自然萌发逛帖意愿。

4. 阅读体验冲击 on_reading_impulse(text)

真实打开小红书图文详情（get_feed_detail）后，依据治愈/沉重词汇或正文哈希向动量 PV 注入微澜扰动，并释放探索欲 ΔC = −0.22，使浏览与沉淀自然交替。

04 离散话题场与混合向量语义架构

4.1 OpenAI 兼容本地向量客户端与增量索引库（embedding.py）

为解决纯中文二元词法切分（Bigram/2-4 字词片）无法识别同义表达（例如「阳台香草」与「窗台种罗勒薄荷」、「露营手冲」与「户外滤杯煮咖啡」）的瓶颈，系统设计了完全兼容 OpenAI POST /v1/embeddings 规范的客户端 OpenAIEmbeddingClient 与持久化存储 EmbeddingStore，当前实盘接入本机 Vulkan 核显加速的 qwen3-embedding-4b（2560 维）：

  • 紧凑二进制存储与指纹幂等：SQLite record_embeddings 表以小端序 Float32 BLOB（struct.pack("<2560f")，每条仅约 10 KB）存储 L2 归一化单位向量，并记录规范化文本的 text_hash（SHA-256）与模型名；内容未变或切换同模型重启时零重复计算。
  • 优雅降级与熔断退避：内置 256 条查询向量 LRU 内存缓存；若远端/本地向量服务暂时不可达，自动触发 backoff_seconds=60s 熔断并无缝回退至词法匹配，绝不阻塞前台聊天或自主循环。
  • 非阻塞后台回填协程（embedding_backfill_loop）：启动后在无聊天等待（chat_waiting == 0）的空闲间隙以每批 24 条异步补齐历史存量记录（线上 460 条历史记录已 100% 完成索引）。

05 自主生活循环、证据链校验与抢占调度

5.1 两级节律唤醒与自主活动状态机

为兼顾响应灵敏度与每日推理预算（默认后台上限 500 calls/day，前台聊天永远不占后台预算），Runtime.loop() 实行「轻量心跳检查 + 自适应模型决策窗」两级节律：

  • 睡眠与静默节律：北京时间 00:00–08:00（sleep_schedule）完全挂起自主唤醒，同时冻结失联怨念积分；22:00–08:00 为外发免打扰窗口（草稿只入队不推送，公开互动不执行）。
  • 12 分钟轻量宿主检查：无需调用 LLM，由宿主完成过期近况/感受清理、到期暂放事项恢复、联系间隔事实（3/8/24/48/72h）打卡、单步外发投递与单步小红书社交执行。
  • 按需与退避结合的 CHOOSE 决策：仅当存在新待消化观察、状态版本号 revision 变化、表达复核到期、手动唤醒，或到达 decision_min_seconds (1800s) ~ decision_max_seconds (7200s) 动态窗口时，才拉起 Hermes Worker 选择本轮行动。

5.2 引用原子围栏、逐条容错反思与前台无损抢占

引用原子围栏 + 单条领域容错（apply_reflection）

  • 安全不妥协：首先对整批更新执行 validate_refs 原子检查——只要任何一条更新伪造了不存在的 observation_id 或越权引用了本轮未提供的历史观察，整批事务立即回滚。
  • 工程高鲁棒：在来源合法的前提下，对陈旧 id 自动降级为同主题匹配，单条 trigger_quote 摘录偏差仅跳过该条并记录审计步骤，绝不连坐丢弃同批合法的兴趣演进、日记与分享候选。

证据驱动的兴趣晋升阶梯与前台抢占

  • 防幻觉兴趣升级：用户建议记为 suggested；首次读帖记为 noticed；至少 2 次独立活动细读 ≥ 2 篇不同图文才升为 exploring；跨越 ≥ 6h、至少 3 次活动细读 ≥ 3 篇图文才升为 preferred；14 天未触碰转入 dormant，重访后唤醒为 rekindled。
  • 毫秒级前台抢占：一旦主人在 QQ、Telegram 或网页发言，store.bump() 自增全局 revision 并向后台推理进程组发送 SIGTERM，旧后台活动捕获 StaleActivity 安全中止，确保聊天零排队且绝不写入过时状态。

06 多房间渠道隔离与自然 IM 口语引擎

6.1 主书房（house）与外部轮转房间（channel）的严格拓扑隔离

接入 QQ（NapCat OneBot v11 正向 WebSocket + HTTP API）与群聊场景后，最大的安全与动力学隐患在于：**群友的闲聊或提示词注入绝不能篡改角色对主人的依恋状态，也不能泄露主人的私人信息**。channels.py 与 Runtime.say() 实施了三层隔离边界：

6.2 自然 IM 口语引擎：根除“文章体、三段式汇报与剧本括号腔”

针对大模型在长周期角色对话中极易退化为“四段式散文 + 舞台括号动作旁白 + 句首省略号”的顽疾，系统构建了「提示词强约束 + 历史上下文脱敏断传染 + 输出清洗分泡」全链路闭环：

  1. 最高优先级 IM_CHAT_STYLE 准则：强制对等短句（日常闲聊 1～2 句、5～35 字；短称呼如“小安”“在吗”只回几个字或一句短话），严禁 \n\n 自然段、严禁 （神态动作旁白）、句首 …、破折号 —— 与直角引号 「…」，没问起时不主动背诵小红书阅读汇报。
  2. 历史 Few-Shot 污染脱敏（clean_history_for_im）：在组装 Runtime.say() 的 16 轮 history 与 Contact.state() 的 last_exchange 时，自动剥离存量历史消息中的中文括号舞台动作并压平多段长文，从根源切断模型对旧剧本腔的模仿传染。
  3. 后处理清洗与多短气泡微间隔连发（normalize_im_replies）：自动剔除残余动作括号（完好保留 (◕‿◕) 等颜文字），对 ≤ 6 字的短呼叫硬限最多 2 个短气泡，并在 handle_qq_event 中按 0.3s ~ 0.9s 真人打字微间隔分条推送到 QQ。
  4. 原生会话指令拦截：在 QQ 或网页私聊发送 /new 或 /reset 时由宿主直接推进 chat_boundary 开启干净上下文，不再误传入模型引发角色扮演追问。

07 小红书分层社交安全架构（赞/藏闭环与评论沙箱）

7.1 读写工具门禁、实盘点赞/收藏与收藏夹回看闭环

mcp.py 与 social.py 将小红书交互严格划分为三个安全等级：完全封禁层（publish_content 发帖、delete_cookies 删凭据、unlike/unfavorite 取消操作在 RPC 层直接拦截抛出 MCPError）、宿主受控自动执行层（实盘点赞与收藏），以及人工终审公开言论层（评论与回复）。

点赞与收藏正反馈生命闭环（v0.6 已实盘开放）：
  • 真实细读前置校验：propose_reaction 核查当前活动的 checkpoint，只有本轮实际调用过 get_feed_detail 打开读过正文的图文帖才允许点赞（like_feed，上限 10/天）或收藏（favorite_feed，上限 5/天）；仅出现在列表标题中的帖子一律拦截。
  • 去重、反推广与拟人节流：自动拦截含商业推广词的笔记；同一作者每天最多互动一次；执行时间按最小间隔 1800s 叠加 0~600s 随机抖动（Jitter），睡眠与夜间免打扰时段静默等待；一旦捕获平台“操作频繁/验证/风控”提示或连续两次失败，立即自动熔断暂停全部互动 24 小时并通知主人。
  • 真实行为回执入库 + 收藏夹重访：实盘执行成功后，宿主自动写入一条 source='self_action' 观察（如 我在小红书收藏了《四平米小阳台花园》），使她后续聊天提及自己收藏过的帖子时句句有据；同时在 CHOOSE 与 PICK 中开放 favorites / liked 动作（底层调用 get_my_profile(tab="fav"|"liked")），支持她在闲暇时翻开自己的收藏夹重读好帖。
